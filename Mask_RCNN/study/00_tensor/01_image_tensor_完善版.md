# 2. 图片与 Tensor

## 2.1 普通图片通常是什么结构？

普通彩色图片通常可以表示为：

```text
H × W × C
```

例如一张 640×640 的 RGB 图片：

```text
640 × 640 × 3
```

其中：

| 符号 | 含义 | 示例 |
|---|---|---:|
| H | Height，高度 | 640 |
| W | Width，宽度 | 640 |
| C | Channel，通道数 | 3 |

RGB 图片的 3 个通道分别是：

```text
R：Red
G：Green
B：Blue
```

因此，一个像素位置不是只有一个数字，而是有 3 个数字：

```text
[R, G, B]
```

例如某个像素可能是：

```text
[230, 120, 50]
```

---

## 2.2 为什么 H 对应“行”，W 对应“列”？

可以把图像看成一个二维矩阵：

```text
(H=0,W=0)  (H=0,W=1)  (H=0,W=2) ...
(H=1,W=0)  (H=1,W=1)  (H=1,W=2) ...
(H=2,W=0)  (H=2,W=1)  (H=2,W=2) ...
```

因此：

```text
H = 行索引（竖直方向）
W = 列索引（水平方向）
```

记忆方式：

- Height：从上往下数，第几行
- Width：从左往右数，第几列

---

# 3. PyTorch 为什么常用 BCHW？

PyTorch 的 `Conv2d` 通常接收：

```text
B × C × H × W
```

即：

```text
Batch × Channel × Height × Width
```

例如：

```python
x = torch.randn(1, 3, 640, 640)
```

得到：

```text
x.shape = [1, 3, 640, 640]
```

对应：

| 维度 | 含义 | 当前值 |
|---|---|---:|
| B | Batch，一次处理几张图片 | 1 |
| C | Channel，通道数 | 3 |
| H | Height，高度 | 640 |
| W | Width，宽度 | 640 |

可以把：

```text
x[B, C, H, W]
```

理解为：

```text
x[第几张图片, 第几个通道, 第几行, 第几列]
```

例如：

```python
x[0, 1, 100, 200]
```

表示：

```text
第 0 张图片
第 1 个通道
第 100 行
第 200 列
```

最终得到一个具体数值。

# 4. `torch.randn()` 是什么？

```python
x = torch.randn(1, 3, 640, 640)
```

这里并没有读取真实图片，而是创建一个形状为：

```text
[1, 3, 640, 640]
```

的随机 Tensor。

`torch.randn()` 中的数值来自标准正态分布：

```text
均值 = 0
方差 = 1
```

数值可能类似：

```text
0.52
-1.23
0.09
2.17
...
```

这只是为了练习 Tensor 结构。

## `randn` 和 `rand` 的区别

| 函数 | 分布 | 特点 |
|---|---|---|
| `torch.randn()` | 标准正态分布 | 可以出现负数 |
| `torch.rand()` | `[0,1)` 均匀分布 | 全部非负 |

当前阶段重点不是随机数本身，而是：

```text
shape 和索引规则
```

# 5. Batch 是什么？

如果一次只处理 1 张图片：

```text
B = 1

[1, 3, 640, 640]
```

如果一次处理 8 张图片：

```text
B = 8

[8, 3, 640, 640]
```

因此：

```text
batch_size = 8
```

表示一次将 8 张图片组成一个 batch 输入模型。

# 6. Tensor 索引最重要的规则

假设：

```text
x.shape = [B, C, H, W]
```

例如：

```text
x.shape = [1, 3, 640, 640]
```

## 6.1 `:` 表示该维度全部保留

例如：

```python
x[:, 0]
```

完整写法可以理解为：

```python
x[:, 0, :, :]
```

其中：

```text
第 1 个位置：:   → B 维全部保留
第 2 个位置：0   → C 维取索引 0
第 3 个位置：:   → H 维全部保留
第 4 个位置：:   → W 维全部保留
```

所以：

```python
x[:, 0]
```

表示：

```text
所有图片的第 0 个通道
```

对于 RGB 输入：

```text
0 → R
1 → G
2 → B
```

---

# 7. 整数索引为什么会“降维”？

例如：

```python
x[:, 0]
```

原始 shape：

```text
[B, C, H, W]

[1, 3, 640, 640]
```

在 C 维使用整数索引 `0` 后：

```text
C 维被选定为一个具体元素
→ 该维度消失
```

所以：

```text
x[:, 0].shape
= [1, 640, 640]
```

正式描述：

> **整数索引（integer indexing）通常会移除对应维度。**

记忆方法：

> 整数索引是在某一层中“拿出一个具体元素”，所以这一层外壳不再保留。

---

# 8. 切片为什么会保留维度？

比较：

```python
x[:, 0]
```

和：

```python
x[:, 0:1]
```

## 整数索引

```python
x[:, 0]
```

结果：

```text
[1, 640, 640]
```

C 维消失。

## 切片索引

```python
x[:, 0:1]
```

其中：

```text
0:1
```

表示数学意义上的左闭右开区间：

```text
[0, 1)
```

虽然实际上只取了第 0 个通道，但它仍然是“一个范围”。

因此 C 维仍然存在，只是长度从 3 变成 1：

```text
[1, 1, 640, 640]
```

正式描述：

> **切片（slicing）通常保留对应维度，只改变该维度的长度。**

---

# 9. `x[:, 0]` 与 `x[:, 0:1]` 对比

| 操作 | 含义 | shape | 是否保留 C 维 |
|---|---|---|---|
| `x[:,0]` | 取第 0 个通道 | `[1,640,640]` | 否 |
| `x[:,0:1]` | 切片取第 0 个通道 | `[1,1,640,640]` | 是 |

为什么有时必须保留维度？

因为很多卷积层要求输入是：

```text
[B, C, H, W]
```

如果变成：

```text
[B, H, W]
```

则已经不再符合常规 `Conv2d` 输入格式。

---

# 10. 从 Tensor 中取一个 3×3 小区域

例如：

```python
x[0, 0, 0:3, 0:3]
```

逐维解释：

```text
B = 0      → 第 0 张图片，整数索引，B 维消失
C = 0      → 第 0 个通道，整数索引，C 维消失
H = 0:3    → 第 0～2 行，切片，H 维保留，长度 3
W = 0:3    → 第 0～2 列，切片，W 维保留，长度 3
```

最终：

```text
shape = [3, 3]
```

因此打印出来就是一个二维矩阵：

```text
tensor([
    [ ... , ... , ... ],
    [ ... , ... , ... ],
    [ ... , ... , ... ]
])
```

它可以理解为：

> 第 0 张图、第 0 个通道左上角的 3×3 区域。

---

# 11. 一个空间位置上的通道向量

例如：

```python
x[0, :, 100, 200]
```

解释：

```text
B = 0      → 第 0 张图片
C = :      → 所有通道
H = 100    → 第 100 行
W = 200    → 第 200 列
```

B、H、W 都用了整数索引，因此它们对应的维度被移除。

只剩：

```text
C
```

对于 RGB 输入：

```text
x.shape = [1, 3, 640, 640]
```

所以：

```text
x[0, :, 100, 200].shape
= [3]
```

它表示该空间位置的：

```text
[R, G, B]
```

三个值。

---

# 12. 一个非常重要的认识：空间位置上有一个 C 维向量

对于：

```text
[B, C, H, W]
```

固定：

```text
B
H
W
```

之后：

```text
x[b, :, h, w]
```

剩下的就是一个：

```text
C 维向量
```

RGB 图片中：

```text
C = 3
```

所以一个位置是：

```text
[R, G, B]
```

经过 CNN 后：

```text
C 可能变成 64、256、512……
```

于是同一个空间位置就可能变成：

```text
[f1, f2, f3, ..., f64]
```

这就是后面理解 CNN feature map 的关键。

---

# 13. RGB 的 3 个通道和 CNN 的 64 个通道不是一回事

## 13.1 RGB 的 3 个通道

这是输入图像本身的数据结构：

```text
R
G
B
```

即：

```text
[B, 3, H, W]
```

## 13.2 CNN 的 64 个通道

例如：

```python
conv = torch.nn.Conv2d(
    in_channels=3,
    out_channels=64,
    kernel_size=3,
    stride=1,
    padding=1,
)
```

表示：

```text
输入通道数 = 3
输出通道数 = 64
```

输入：

```text
[B, 3, H, W]
```

输出：

```text
[B, 64, H, W]
```

这里的 64 不再是颜色，而是：

> **64 个学习得到的特征通道（feature channels）。**

入门阶段可以把这些特征粗略理解为：

```text
边缘
方向
颜色组合
纹理
局部形状
……
```

但真实网络中的单个通道并不一定能直接用一个人类词语解释。

---

# 14. 为什么 `out_channels=64` 会产生 64 个 feature map？

可以先这样理解：

```text
输入：

3 × H × W
│
├── Filter 1  → Feature Map 1
├── Filter 2  → Feature Map 2
├── Filter 3  → Feature Map 3
│
│   ...
│
└── Filter 64 → Feature Map 64

输出：

64 × H × W
```

因此：

```python
out_channels=64
```

表示这一层将输出：

```text
64 张 feature map
```

或者说：

> 每一个 `(H,W)` 空间位置，都从原来的 3 维 RGB 描述，被映射成了一个 64 维特征向量。

这是 Day 1 最重要的结论之一。

---

# 15. 卷积核的权重 shape

对于：

```python
nn.Conv2d(
    in_channels=3,
    out_channels=64,
    kernel_size=3
)
```

可以查看：

```python
print(conv.weight.shape)
```

得到：

```text
torch.Size([64, 3, 3, 3])
```

PyTorch 中卷积层权重的排列顺序是：

```text
[C_out, C_in, K_h, K_w]
```

所以：

```text
[64, 3, 3, 3]
```

表示：

| 数值 | 含义 |
|---:|---|
| 64 | 输出通道数 / filter 数量 |
| 3 | 输入通道数 |
| 3 | kernel height |
| 3 | kernel width |

单个输出通道对应的卷积核权重可以看成：

```text
[3, 3, 3]
```

即：

```text
[C_in, K_h, K_w]
```

它在空间上看一个 3×3 区域，同时覆盖全部 3 个输入通道。

> 注意：这里说“一个 filter 学一种特征”只是入门近似理解。更准确地说，一个输出通道由该 filter 对输入局部区域进行加权计算产生。

具体“一个 `[3,3,3]` filter 如何计算出一个数”，放到 Day 2 的 Conv2d 中继续学习。

# 16. x 和 y 一定不要混淆

示例代码中：

```python
x = torch.randn(1, 3, 640, 640)

y = conv(x)
```

因此：

```text
x = 卷积前的输入
y = 卷积后的输出
```

所以：

```text
x.shape = [1, 3, 640, 640]
y.shape = [1, 64, 640, 640]
```

卷积不会自动修改原来的 `x`。

## 同一个空间位置的比较

卷积前：

```python
x[0, :, 100, 200].shape
```

结果：

```text
[3]
```

表示：

```text
[R, G, B]
```

卷积后：

```python
y[0, :, 100, 200].shape
```

结果：

```text
[64]
```

表示：

```text
[f1, f2, f3, ..., f64]
```

因此：

```text
输入图片某个位置：

[R, G, B]
3 个数字

        ↓ Conv2d

特征图某个位置：

[f1, f2, f3, ..., f64]
64 个数字
```


# 18. 真实图片为什么经常需要 HWC → CHW？

许多图片读取工具得到的 NumPy 数组常见排列是：

```text
H × W × C
```

而 PyTorch 单张图片的卷积输入通常需要：

```text
C × H × W
```

所以真实项目中经常看到：

```python
image = image.permute(2, 0, 1)
```

含义是：

```text
HWC
 ↓
CHW
```

再增加 Batch 维：

```text
CHW
 ↓
BCHW
```

这个操作以后在 DataLoader、数据预处理和模型推理代码中会经常出现。

Day 1 只需要知道这个概念，不要求深入掌握 `permute()`。

# 19. Shape 推导表

假设：

```text
x.shape = [1, 3, 640, 640]
```

| 表达式 | 含义 | 结果 shape |
|---|---|---|
| `x` | 完整 Tensor | `[1,3,640,640]` |
| `x[0]` | 第 0 张图片 | `[3,640,640]` |
| `x[0:1]` | 第 0 张图片，但保留 B 维 | `[1,3,640,640]` |
| `x[:,0]` | 所有图片的第 0 个通道 | `[1,640,640]` |
| `x[:,0:1]` | 同上，但保留 C 维 | `[1,1,640,640]` |
| `x[0,0]` | 第 0 张图、第 0 通道 | `[640,640]` |
| `x[0,:,100,200]` | 一个空间位置的全部 RGB | `[3]` |
| `x[0,0,100,200]` | 一个具体数值 | `[]` |
| `x[:,:,0:3,0:3]` | 全部图片、全部通道左上角 3×3 | `[1,3,3,3]` |

## 为什么最后可能出现 `torch.Size([])`？

例如：

```python
x[0, 0, 100, 200]
```

B、C、H、W 四个维度全部使用整数索引。

所以四个维度全部被移除。

最终得到：

```text
0 维 Tensor
```

其 shape 为：

```text
torch.Size([])
```

这不是 `[1]`。

# 21. Day 1 必须记住的核心结论

```text
普通图片常见：

HWC

↓

PyTorch Conv2d 常见：

BCHW
```

```text
x[B,C,H,W]
```

```text
整数索引
→ 选一个具体元素
→ 对应维度通常消失
```

```text
切片索引
→ 选一个范围
→ 对应维度通常保留
```

```text

[B,3,H,W]

Conv2d

↓

```

最关键的一句话：

> **RGB 的 3 个 channel 表示输入颜色信息；CNN 的 64 个 feature channels 表示网络学习得到的 64 维特征描述。两者都叫 channel，但语义不同。**
